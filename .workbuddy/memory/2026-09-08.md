# 2026-09-08 工作日志

## Video Scissors — 新增「多切片 + 拼接」功能

需求:支持多个切片,各自裁剪后拼接成一个输出。

### 改动
- **后端** server.js 新增 `POST /api/trim-multi`:
  - 入参 `{ filename, mode, segments:[{start,end}] }`
  - 逐个切片 ffmpeg 裁剪 → 临时片段 → 写 concat 清单 → `ffmpeg -f concat -safe 0 -i list.txt -c copy` 合并
  - 进度汇总 0–100%(各切片按 (i+frac)/N*90 +1, 拼接 95→99),轮询复用 `/api/status/:jobId`
  - 校验: 空/超 100 切片/模式非法/时间越界/文件缺失;临时片段与清单在 finally 中清理
  - 输出命名 `merged-<ts>-<rand>.mp4`
- **前端** index.html / style.css / app.js:
  - `state.segments` 数组;「把当前选区加入切片」按钮;切片列表(起止/时长/删除/点击回填选区);「合并导出 (N)」按钮(无切片禁用)
  - 导出改为调 `/api/trim-multi`,结果区文案改为「已合并导出」
- **模式策略调整(重要)**: 快速/精确现在都改为重新编码(libx264/aac),不再用流复制:
  - 快速: `preset veryfast, crf 23`;精确: `preset medium, crf 18`;均输出 mp4

### 关键发现(可复用)
- **流复制 `-c copy` + `-ss` 会吸附关键帧,无法做任意时间点精确裁剪**;多片段拼接会把误差放大(实测 testsrc 上切出 4.08s/10.08s,合并成 14.16s 而非 6s)。
- `-ss` 放在 `-i` 前后对 copy 模式都不准;只有重新编码才能得到帧级精确切片,且拼接后总时长才正确(实测每段 3.0s、合并 6.0s)。
- drawtext 滤镜在本机 ffmpeg 会 segfault(字体/fc 问题),测试视频改用纯 testsrc 不带文字叠加。
- 结论: 多切片拼接必须用 re-encode 切片 + concat demuxer `-c copy`(片段已是统一 h264/aac)。

### 验证
- 快速/精确模式多切片(2 段 / 3 段)输出时长均=各切片之和(6.0s)
- 参数校验、单切片走 multi、下载(47705 字节有效)均通过
- 服务重启后运行于 http://localhost:3000(后台任务 YnLAIM)

### 待与用户确认
- 原「快速=无损流复制」已改为「快速转码」,牺牲了无损以换取多切片拼接正确性。如需要无损单片段,可另加仅单片段的流复制分支。

## 导出逻辑优化:分别导出 + 按钮随切片数量变化

需求:除合并导出外,支持把多个切片分别导出为独立文件;按钮数量/文案随切片数变化(1 个只显示导出按钮,≥2 个显示「合并导出 (N)」+「导出 N 个单独片段」)。

### 改动
- **后端** server.js 新增 `POST /api/trim-separate`:
  - 入参同 multi;逐个切片裁剪 → 各自保留为 `clip-<jobId>-<i>.mp4` 输出(不再拼接)
  - 成功后返回 `files:[{url,filename},...]`;进度按 (i+frac)/N 汇总;失败时清理已生成的片段
- **前端**:
  - index.html: 导出区改为 `mergeBtn`(合并)+ `separateBtn`(单独,默认 hidden);结果区改为 `resultMsg` + `resultList` 容器(支持多文件列表)
  - app.js: `updateExportUI()` 按 segments 数量切换按钮显隐与文案;新增 `startExport(type)` 分发到两个接口;`pollStatus(jobId,type)` 对 separate 调 `showResults(files)` 渲染多文件;`showResults`/`renderResultItems` 生成每个片段的 video+下载链接
  - style.css: `.export-actions`(纵向 gap)、`.result-list`/`.result-item` 多文件卡片样式
- 验证: separate 3 段 → 返回 3 个文件各 2.0s,正确。

### 当前导出按钮规则
- 0 切片: 两个按钮都隐藏(显示提示)
- 1 切片: 仅显示「✂️ 导出片段」(走合并接口,产出单文件)
- ≥2 切片: 显示「✂️ 合并导出 (N)」+「📦 导出 N 个单独片段」

## Bug 修复: 合并导出按钮无法点击

现象: 有切片时(尤其 2 个)「合并导出」按钮点不动。
根因: index.html 中 `mergeBtn` 初始带 `disabled` 属性,而 `updateExportUI()` 只切换 `.hidden` 与文案,从未清除 `disabled`,导致按钮一直禁用(单独导出按钮无该属性故可点)。
修复: `updateExportUI()` 现统一管理 `disabled` —— n>=1 时 `mergeBtn.disabled=false`,n===0 时两者禁用。改 public/app.js,纯前端,刷新即生效。

## 新增: 多片段「一次性下载全部 (ZIP)」

需求: 多片段分别导出时,新增一个按钮可一次性下载全部切片(打包 ZIP),同时保留原来逐一下载逻辑。

### 改动
- **依赖**: `npm install archiver`(^8.0.0,纯 JS,无原生编译)。注意 v8 导出形态变化:`require('archiver')` 返回对象而非函数,需用 `new archiver.ZipArchive({zlib:{level:0}})`(level 0 = store,视频已压缩不再重压)。
- **后端** server.js `/api/trim-separate`:
  - 切片全部生成后,若 `total > 1` 则用 archiver 打包 `clips-<jobId>.zip`(输出目录,经 `/outputs` 静态服务),条目名用 `originalName` 去扩展名 + `_clipN.mp4`;level 0 存储。
  - 成功时额外返回 `zipUrl` / `zipName`;失败时清理半截 zip。
  - 前端请求体新增 `originalName` 字段(用于 zip 内友好文件名)。
  - 单片段分别导出不生成 zip(无需)。
- **前端** public/app.js: `startExport` 请求体带 `originalName`;`pollStatus` 对 separate 传 `data.zipUrl/zipName` 给 `showResults`→`renderResultItems`;当 `files.length > 1 && zipUrl` 时,在结果列表顶部插入「📦 一次性下载全部 N 个片段 (ZIP)」卡片 + 主按钮下载 zip。逐片段下载按钮逻辑原样保留。
- **样式** style.css: `.result-all` 高亮卡片 + `.result-all-label` 标签。

### 验证
- 3 段分别导出(原画质): 返回 3 个 clip 文件 + zipUrl;下载 zip 内含 `mysource_clip1/2/3.mp4`(友好命名、大小匹配),验证通过。
- 修复过程: 首次因 archiver v8 API 误用 `archiver('zip')` 报 "archiver is not a function",改为 `new archiver.ZipArchive()` 后正常。
- 服务重启后运行于 http://localhost:3000。
